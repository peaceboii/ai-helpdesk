# Project Reflection

1. **What worked**: The complete pipeline from data preprocessing to Streamlit deployment was successfully built. Text cleaning and TF-IDF effectively converted raw text into structured features, and the custom priority logic successfully flags urgent tickets based on keywords.
2. **Limitations**: The model's baseline accuracy (around 42%) reflects the difficulty of classifying overlapping customer support categories when using synthetic or sparsely labeled datasets. The synthetic HR dataset achieved 100% accuracy, highlighting that real-world nuanced data is much harder to separate than clearly-defined synthetic data.
3. **What additional data would improve accuracy**: Collecting real-world, historically categorized support tickets from the actual company would drastically improve accuracy. Additionally, metadata like user profiles, timestamps, or product categories could be included as tabular features alongside the text data.
4. **Why Logistic Regression/Naive Bayes was chosen**: Both are fast, robust baselines for text classification with TF-IDF. Naive Bayes performs well with word counts, but Logistic Regression was ultimately chosen because it can weigh feature correlations better, edging out slightly higher F1 scores. They are easily interpretable and very lightweight compared to LLMs.
5. **How this could scale to production**: The current `joblib` artifacts can be deployed inside a Docker container behind a FastAPI endpoint. The Streamlit app can be used by internal agents, while the API integrates directly into the company's ticketing software (like Jira or Zendesk) for automatic categorization upon ticket creation.
